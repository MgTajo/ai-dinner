# Your Superteam agent service

A Node.js + TypeScript backend (an [Express](https://expressjs.com) HTTP server) generated by **Superteam Agent Studio**. You don't need any blockchain experience to run it.

## Quick start

You need [Node.js](https://nodejs.org) 20.12 or newer (22 LTS recommended). Check with `node -v`.

```bash
npm install
cp .env.example .env.local   # then fill in the values described below
npm run dev
```

Open http://localhost:3000 (or `curl http://localhost:3000`). It answers with JSON listing every feature included in this service.

| Command | What it does |
| --- | --- |
| `npm run dev` | Runs the server locally and restarts it when you save a file |
| `npm run build` | Compiles TypeScript into `dist/`, the same way a deploy would |
| `npm run start` | Runs the compiled server from `dist/` |
| `npm run typecheck` | Checks TypeScript types only (including `scripts/` and `examples/`) |

## Keeping secrets secret

- Put keys only in **`.env.local`**. It is in `.gitignore`, so git won't commit it. The server loads it on start.
- Never send a key back in a response, and never log it.
- If a key ever ends up in git or a screenshot, revoke it and make a new one.

## Project layout

```
src/server.ts   starts the server and loads every file in src/routes
src/routes/     one file per feature; each adds its endpoints to the app
src/lib/        helpers for each feature
scripts/        command-line tools (run with npm run …)
examples/       small programs that call this service
studio.manifest.json   what Agent Studio generated, for reference
```

To add your own endpoint, create `src/routes/my-thing.ts`:

```ts
import type { Express } from "express";

export default function register(app: Express) {
  app.get("/api/hello", (_req, res) => {
    res.json({ hello: "world" });
  });
}
```

## Gemini AI

**What you get:** `POST /api/chat`, an endpoint that asks Google Gemini using the official [`@google/genai`](https://www.npmjs.com/package/@google/genai) SDK.

**Setup (2 minutes, free):**

1. Go to https://aistudio.google.com/apikey and sign in with a Google account.
2. Click **Create API key** and copy it.
3. In `.env.local` set `GEMINI_API_KEY=your-key`, then restart `npm run dev`.

**Try it:**

```bash
curl -X POST http://localhost:3000/api/chat -H "Content-Type: application/json" -d '{"prompt":"Say hi"}'
```

**How it works:** callers talk to *your* service; only the service talks to Gemini, so the key never leaves your server. The code is in `src/lib/ai/gemini.ts` and `src/routes/chat.ts`. To use a different model set `GEMINI_MODEL` (default `gemini-flash-latest`).

**If it fails:** "GEMINI_API_KEY is not set" means `.env.local` is missing the key or you didn't restart the server. A 502 means Gemini rejected the call; the terminal running `npm run dev` shows the reason (often an invalid key or a free-tier rate limit).

## Internet-native payments (x402 on Solana devnet)

**What it is:** [x402](https://www.x402.org) brings back the HTTP status code `402 Payment Required`. A server answers "this costs $0.01"; the caller pays and repeats the request; the server checks the payment and responds. No sign-ups, cards or API keys. Programs (like AI agents) can pay for things on their own.

**No real money.** This template only works on **Solana devnet**, a test network where tokens are free and worthless. It refuses any other network on purpose.

### Words you'll see

| Word | Meaning |
| --- | --- |
| Wallet / keypair | A public **address** (safe to share, like an account number) plus a **secret key** (like a password; never share it). |
| Devnet | Solana's test network. Free test tokens, no value. |
| USDC | A token worth $1 on mainnet. Here you use **devnet USDC**, which is free test money. |
| Facilitator | A service that checks a payment and submits it to Solana for you. This app uses the free test facilitator at `https://x402.org/facilitator`. It also pays the small network fee, so you don't need SOL. |
| `PAYMENT-REQUIRED` / `PAYMENT-SIGNATURE` / `PAYMENT-RESPONSE` | The HTTP headers x402 V2 uses for the price, the signed payment and the receipt. |

### Setup

1. **Where payments arrive (seller).** Run `npm run keygen -- --pay-to`. This puts a fresh devnet address in `PAY_TO_ADDRESS` in `.env.local`. (Or paste your own devnet address from a wallet app such as Phantom or Solflare.)
2. **Who pays (buyer/agent).** Run `npm run keygen`. This creates a throwaway devnet key in `AGENT_PRIVATE_KEY` and prints its address.
3. **Get free test USDC.** Go to https://faucet.circle.com, choose **Solana Devnet**, and request USDC for **both** addresses: the buyer (so it can pay) *and* the seller (so it has a USDC account to receive into; x402 does not create one for you).
4. **Check:** `npm run wallets` should show ✓ for both.
5. Restart `npm run dev`.

> ⚠️ `AGENT_PRIVATE_KEY` is a secret. Use a throwaway key made for this project, never a wallet that holds real money.

**Code:** `src/lib/payments/server.ts` (charge for an endpoint with `paidRoute(...)`, built on [`@x402/express`](https://www.npmjs.com/package/@x402/express)), `src/lib/payments/client.ts` (a `fetch` that pays automatically), `src/lib/payments/config.ts` (devnet-only settings).

**Paying an address directly (the AI Race's on-chain payment stage):** `src/lib/payments/transfer.ts` has `payUsdc(signer, { to, amountUsdc, memo })`. It sends devnet USDC from the agent wallet to any address, with an optional memo, creates the recipient's USDC account if needed, and waits until devnet confirms. It returns `{ signature }`. Pass the spending module's tracker as `{ guard }` to keep it within your budget. `npm run test:transfer` checks it offline. The agent wallet needs devnet SOL for fees (faucet.solana.com) and devnet USDC (faucet.circle.com); if it doesn't, the error says which.

**Charge for your own endpoint** in any file in `src/routes/`:

```ts
import { paidRoute } from "../lib/payments/server.js";

app.get("/my-data", paidRoute("GET /my-data", () => ({ price: "$0.02", description: "My data" })), (_req, res) => {
  res.json({ secret: "only for paying callers" });
});
```

The `"GET /my-data"` string must match the method and path you mount it on (`:id` style parameters are fine). If it doesn't, the endpoint answers 500 instead of being served for free.

## AI Race adapter

**What you get:** the two endpoints the AI Race verifier calls, `GET /agent-studio/v1/health` and `POST /agent-studio/v1/tasks`, already speaking the race protocol (ASRP/1): they check the verifier token, echo the nonce and wrap your answers. `GET /race` shows which task types you've built.

**What you build:** the AI logic, one function per task type in `src/race/handlers.ts`. Each race layer tests one capability (answering with a model, structured output, tool calling, knowledge, memory, reliability, workflows). They all start as "not built yet" and return a clear error until you write them. `src/race/tools.ts` has `callTool` and `searchSource` for calling the race's tools.

**Setup:**

1. On Agent Studio, open your team page and copy the **verifier token** into `.env.local` as `AGENT_STUDIO_VERIFIER_TOKEN`, then restart `npm run dev`.
2. Write `handlers.respond` (the first layer), for example with the Gemini module: `respond: async (task) => ({ text: await askGemini(String(task.input)) })`.
3. Try it locally: `npm run race:try -- respond "What is 6 x 7?"`.
4. Deploy (for example to Railway or Render, adding the same env var) and paste the public URL on your team page. Then press **Run verification** on the race page.

**Memory on serverless hosting:** the Memory and Context layer checks that your app remembers earlier turns of a conversation. On Vercel (and other serverless hosts) each request can reach a different instance, so history kept in a variable is lost between turns, even though it works locally. Use `memory` from `src/race/memory.ts` and connect a free Upstash Redis database: on Vercel, **Storage → Upstash for Redis → Connect** to your project (it adds `KV_REST_API_URL` and `KV_REST_API_TOKEN`), or create one at upstash.com and set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. Without them, `memory` keeps history in the process, which is fine locally and on an always-on server.

**Tests:** `npm run test:race` checks the protocol handling offline. The race verifier checks your AI logic with fresh inputs on every attempt, so answers can't be hard-coded.

**If it fails:** 401 means the token in your environment doesn't match your team page (rotate it there and copy again). "doesn't handle … yet" means that handler is still the placeholder. The full protocol is in the [verification guide](https://github.com/Db0706/superteam-agent-studio/blob/main/docs/VERIFICATION_SDK.md).

## Spending controls

An agent that pays automatically needs limits. Before every payment the buyer checks:

- **Per-payment cap** (`MAX_PAYMENT_USD`, default `0.10`): anything more expensive is refused before it is signed.
- **Total budget** (`AGENT_BUDGET_USD`, default `1.00`): once this much has been spent, further payments are refused.
- **Only devnet USDC**: prices in any other token are refused.

A payment counts against the budget as soon as it is signed. It is handed back if the seller rejects it. If the network fails halfway, it stays counted, so the budget is never under-counted. The running total is kept in memory and **resets when the server or script restarts**. Save it to a database if you need it to persist.

**Code:** `src/lib/spending/policy.ts` (reads the limits), `src/lib/spending/tracker.ts` (the running total), `src/lib/spending/attach.ts` (plugs the limits into the x402 client, alongside x402's own built-in per-payment cap).

**Test it (no wallet needed):** `npm run test:spending`

## Paid API example

**What you get:**

- `GET /premium-data`: an endpoint that costs `$0.01` (devnet USDC) per call. Change the price with `PAID_API_PRICE_USD`. Replace the handler in `src/routes/premium-data.ts` with whatever you want to sell, such as Gemini output or data.
- `examples/client.ts` (`npm run pay`): a buyer program. It pays with `AGENT_PRIVATE_KEY` within its spending limits and prints the data and the receipt. Other agents can buy from your service the same way.
- `POST /api/buy`: the same buyer running inside your service. It only ever buys from this service's own `/premium-data`. `GET /api/buy` shows the budget.

**Try it** (after the payments setup above, with `npm run dev` running in another terminal):

```bash
curl -i http://localhost:3000/premium-data             # 402 + PAYMENT-REQUIRED header (the price)
npm run pay                                            # pays once, prints the data + receipt
npm run pay -- http://localhost:3000/premium-data 5    # pays 5 times; watch the budget go down
curl -X POST http://localhost:3000/api/buy             # the service's own agent pays once
```

The `PAYMENT-REQUIRED` header is base64 JSON. To read it: `curl -si http://localhost:3000/premium-data | grep -i payment-required | cut -d' ' -f2 | base64 -d`.

A successful payment prints a `receipt` with a `transaction` id. Paste it into https://explorer.solana.com/?cluster=devnet to see it on-chain.

**If it fails:**

| Message | Fix |
| --- | --- |
| `PAY_TO_ADDRESS is not set` | Run `npm run keygen -- --pay-to`, then restart the server |
| `AGENT_PRIVATE_KEY is not set` | Run `npm run keygen` |
| `…simulation_failed…` or `insufficient_funds` | Run `npm run wallets`. The buyer needs devnet USDC, and the seller address needs a USDC account (send it faucet USDC once) |
| `…above the per-payment cap…` / `maxAmountPerPayment` | The price is higher than `MAX_PAYMENT_USD` |
| `…would exceed the budget…` | `AGENT_BUDGET_USD` is used up. Restart the server (or script) to reset it, or raise it |

## Pay.sh

**What it is:** [Pay.sh](https://pay.sh) is a free, open-source tool from the Solana Foundation. Its `pay` command pays HTTP 402 charges for you, using the same x402 protocol as this service. It keeps its own wallet, separate from `AGENT_PRIVATE_KEY`, and it can let AI agents such as Claude Code pay for APIs while they work.

**Install it once:** `brew install pay` (macOS) or `npm install -g @solana/pay`. Check with `pay --version`.

**Try it** (with `npm run dev` running in another terminal):

```bash
npm run paysh              # pays GET /premium-data once from your Pay.sh wallet
npm run paysh -- wallet    # shows that wallet's devnet address and USDC balance
```

The first `npm run paysh` makes a Pay.sh devnet wallet and fails with "payment was refused", because the new wallet is empty. Run `npm run paysh -- wallet`, send that address devnet USDC at https://faucet.circle.com (choose **Solana Devnet**), then run `npm run paysh` again. You can also call `pay` directly: `pay curl http://localhost:3000/premium-data`.

**Let Claude Code use your API:** run `pay claude` in this folder. Claude Code starts with Pay.sh's tools and pays for x402 APIs it calls, such as `http://localhost:3000/premium-data`, from the same wallet.

**Pay.sh's test network:** add `--sandbox` to pay public demo APIs on Pay.sh's hosted test network, which funds a throwaway wallet for you: `npm run paysh -- https://debugger.pay.sh/mpp/quote/AAPL --sandbox`.

**Get listed:** `npm run paysh -- listing your-team` writes `pay-listing/providers/your-team/<this project>/PAY.md`, a listing for the Pay.sh catalog, and checks it with `pay catalog check`. Set `PAYSH_SERVICE_URL` to your deployed `https://` address first. The public catalog only lists APIs paid on Solana **mainnet**, so submit it to https://github.com/solana-foundation/pay-skills once your service takes real money.

**If it fails:**

| Message | Fix |
| --- | --- |
| `The pay CLI is not installed` | `brew install pay` or `npm install -g @solana/pay` |
| `The payment was refused` | Your Pay.sh wallet has no devnet USDC. `npm run paysh -- wallet`, then use the faucet. The seller address needs a USDC account too (see the payments setup) |
| `Could not connect to Surfpool` with `--sandbox` | Pay.sh's hosted test network is down. Leave out `--sandbox` and pay on devnet instead |
